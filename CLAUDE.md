```

  → star schema as tibbles (dim_* / fct_*)

      → Evidence.dev source queries (dashboard/sources/hospital/*.sql)
        → Evidence.dev pages (dashboard/pages/*.md)
```

## Architecture

### 1. Config — `src/generateScripts/simmerConfig.R`

- Time: `dayMinutes`, `workDayMinutes` (8 h), `simDays <- 365`. Sim start `simOrigin` = 2025-01-01 09:00 UTC; `to_datetime()` converts sim minutes to timestamps.
- `resource_definitie`: 20 resources (id, name, type, capacity).
- `aandoeningDimensies`: 33 conditions (id 1–33).
- `aankomst_schema`: quarterly arrival rate (`rate` = 1 / mean inter-arrival minutes).
- `service_schema`: quarterly service-time multiplier.
- `epidemie_*`: bell-curve weight boost for one condition (Infectious Laughter, id 12).
- `capaciteit_schema`: planned capacity changes per resource per day.

### 2. Simulation — `src/generateScripts/simmerImplementatie.R`

Sources the config, runs the simmer model, and builds the star-schema tibbles in memory:
- `dim_aandoening`, `dim_patient`, `dim_behandelkamer`
- `fct_gebeurtenis` — one row per patient × resource visit (`startTijdstip`, `eindTijdstip`, `behandeltijd`, `wachttijd`, `behandelkamerNummer`)
- `fct_behandelkamer` — resource monitor snapshots (servers in use, capacity, queue)

Key mechanics:
- Every resource has a daily work schedule (capacity during the 8 h workday, 0 outside) via `maak_work_schedule()`.
- `service_step()` splits service into chunks that fit in the remaining workday; unfinished service spills over to the next day (tag-based `rollback`).
- Routing: condition → trajectory letter (`aandoening_route`, A–S) → `maak_traject(diagnose_id, behandel_id)`. Every patient goes Reception → one diagnosis room → one treatment room.
- Arrivals: one generator, `from_to()` within the workday each day, inter-arrival via `aankomstDistributie()`.
- Service times: `resource_durations` (min/max per resource) → lognormal around the mean × seasonal multiplier.
- `behandelkamerNummer` is derived after the run via interval scheduling (simmer does not record which server was used).

**Known issue:** `capaciteit_schema` changes are applied with `set_capacity()`, but the daily work schedule overwrites them at the next shift boundary, so they last at most one day.

### 3. Database — `src/databaseScripts/databaseUtils.R`

Run in the same R session after `simmerImplementatie.R` (it uses its in-memory tibbles). Drops and recreates the tables with explicit types and keys, then appends the data. See this script for the authoritative table schemas.

### 4. Dashboard — `dashboard/` (Evidence.dev / Svelte + DuckDB)

- Source queries: `dashboard/sources/hospital/*.sql` (`aankomstOntslag`, `behandeltijd`, `capaciteit`, `totaal`).
- Pages: `index.md` (case/KPI overview), `1. Aankomst.md`, `2. Capaciteit.md`, `3. Wachttijd.md`, `4. Architectuur.md`, `5. Behandeltijd.md`.
- **In transition:** the source queries still select from old table names (`hospital.aankomstOntslag` etc.) that no longer exist in the DuckDB file. Draft replacement queries against the `fct_*`/`dim_*` tables live in `src/sqlScripts/concept*.sql`.

### Legacy / stale scripts

- `src/statsScripts/simmerStatistics.R` and `src/generateScripts/simmerAggregate.R` still reference old objects (`events_wrangle`, `log_aankomst_ontslag`) and partly old `data/...` paths. They will not run against the current implementation without rework.
- The old CSV pipeline (`simmerWriteToDisk.R`, `monthlyAggregate.R`, `output/YYYYMMDD_*.csv`) is archived in `oud/`.

## Simmer API — correct patterns

Claude frequently hallucinates simmer function signatures. Use these anchors (they match the code in this repo).

```r
# Attribute from a function (function form required — not a value)
set_attribute(keys = "aandoeningId", values = aandoeningBepaling)

# Reading an attribute / the clock inside a trajectory function
get_attribute(env, "aandoeningId")
now(env)

# Branching: option function returns a 1-based index (0 = skip); one trajectory per index
branch(route_index, trajA, trajB, ..., continue = TRUE)

# Daily workday capacity schedule (period = one day in minutes)
schedule(timetable = c(0, workDayMinutes), values = c(capacity, 0), period = dayMinutes)

# Rollback to a tagged activity
set_attribute(..., tag = "loop_tag")
rollback("loop_tag", times = Inf)

# Arrivals only inside a daily window
from_to(start_time = 0, stop_time = workDayMinutes, dist = f, every = dayMinutes)

# Runtime capacity change (overwritten by an active schedule at its next tick)
set_capacity("Reception", value = 5)
```

When in doubt about a simmer function, check `?simmer::trajectory` before writing code. Do not infer signatures from memory.

## R Conventions

- Tidyverse (dplyr, tidyr, purrr, tibble) for data wrangling.
- No base-R `for` loops for data transformation — use `group_by() |> summarise()` or `purrr::map()`. (The existing loop that adds capacity generators to `env` is a known exception.)
- Column names in the star schema are camelCase Dutch (`startTijdstip`, `behandelkamerId`, `patientenInWachtrij`); table names use `dim_` / `fct_` prefixes.
- Prefer `|>` (base pipe) over `%>%` in new code.
- Functions should be small and named by intent. Add a one-line comment for non-obvious logic.
- Always `set.seed(42)` in entry scripts. Document any additional seeds inline.
